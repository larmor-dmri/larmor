class larmor.tractography.Tracker(algorithm, *, step_size=None, max_angle=None, cutoff='auto', min_length=None, max_length=None, bidirectional=True, progress=False)#

Tracks streamlines through a field of FODs.

The settings are fixed here and track runs one tracking, from seeds to a tractogram. The algorithm is “det” (deterministic) or “prob” (probabilistic). Lengths are in mm.

The maximum angle limits the turn between two consecutive steps, so the tightest curve it allows has a radius of step / (2 sin(angle / 2)), and the same angle means a different curvature at a different step size. Without a given angle, “det” sets it from the step size so that this radius is 0.65 times the voxel size (about 8.8 degrees at the default step, and no limit for a step above 1.3 voxels); “prob” uses 15 degrees. The run records the radius as “min_radius”.

References

Deterministic (“det”): Tournier J-D, Calamante F, Connelly A. MRtrix: diffusion tractography in crossing fiber regions. Int J Imaging Syst Technol 22 (2012) 53-66. doi:10.1002/ima.22005

Probabilistic (“prob”): Tournier J-D, Calamante F, Connelly A. MRtrix: diffusion tractography in crossing fiber regions. Int J Imaging Syst Technol 22 (2012) 53-66. doi:10.1002/ima.22005

track(fod, output, seeds, *, num_streamlines=None, mask=None, basis='tournier', seed=None, output_seeds=None, n_jobs=-1)#

Tracks streamlines from the seeds, batch by batch.

Parameters:

  • fod (Volume) – The FOD as SH coefficients, (X, Y, Z, C). C tells the layout: the even degrees of a symmetric FOD, or all degrees of an asymmetric one.

  • output (str | Path | None) – The tractogram to write, .tck or .trk, batch by batch. Each streamline carries the EndStatus of both ends as end_status in its streamline data (kept by TRK only). None keeps the streamlines in memory and returns them in the run record, which suits small runs only.

  • seeds (Seeds | SeedStrategy) – Where streamlines start, as fixed Seeds, tracked in order, or an endless source such as MaskSeeds, drawn from batch by batch. A seed without a direction gets one from the algorithm; a seed where none is found counts as no_start.

  • num_streamlines (int | None) – Track until this many are accepted. Defaults to None, which tracks every seed of a Seeds.

  • mask (Volume | None) – Tracking mask; a streamline stops where it leaves it. A point is inside where the scaled value of the mask’s nearest voxel is at least 0.5. Defaults to None, no mask.

  • basis (str) – The FOD’s SH basis. Defaults to “tournier”.

  • seed (int | None) – The run seed, in [0, 2^64), which fixes the seeds drawn and every random number. Defaults to None, which draws one and records it.

  • output_seeds (str | Path | None) – A text file for the seeds of the accepted streamlines, in output order, which read_seeds reads back. Defaults to None.

  • n_jobs (int) – Number of threads, at most the cores; -1 is all cores. Defaults to -1. The result does not depend on it.

Returns:

TractographyRun – The record of the run.

Raises:

ValueError – If an endless seed source has no number of streamlines, num_streamlines is not positive, the mask is not 3D, seed or n_jobs is out of range, the FOD’s lmax is above the supported maximum or its coefficient count fits no SH layout, the resolved min length is not below the max length, the automatic cutoff cannot be measured (no voxel in the mask with a positive DC term or with a peak), or no seed lies on the FOD’s grid or in the mask.

Return type:

TractographyRun

larmor.tractography.build_connectome(nodes, num_nodes, *, weights=None, values=None, symmetric=False, zero_diagonal=False)#

Builds a connectome matrix from the regions of the streamlines’ endpoints.

Every streamline whose two endpoints are both in a region (nodes 1 to num_nodes) adds to the edge between its two regions, an entry of the upper triangle (row <= column); one that ends twice in the same region adds to the diagonal. Streamlines with an endpoint in no region (node 0) are left out. Without values, an edge holds the number of its streamlines, or the sum of their weights. With values, it holds their mean value, weighted by the weights if given, and 0 where no streamline connects the two regions.

Parameters:

  • nodes (ndarray) – (S, 2) the regions of each streamline’s endpoints, as from endpoint_nodes.

  • num_nodes (int) – The number of regions, with one row per label from 1 to num_nodes; usually the largest label of the parcellation (len(node_names(parcellation))). Sparse labels give a row for every unused label.

  • weights (ndarray | None) – (S,) one weight per streamline, such as SIFT2’s. Defaults to None, every streamline counting 1.

  • values (ndarray | None) – (S,) one value per streamline, such as its length (streamline_lengths), to average over each edge. Defaults to None.

  • symmetric (bool) – Whether to fill the lower triangle with the upper one. Defaults to False, which leaves the lower triangle 0.

  • zero_diagonal (bool) – Whether to set the diagonal (connections of a region to itself) to 0. Defaults to False.

Returns:

(num_nodes, num_nodes) float64; row and column i are region i + 1.

Raises:

ValueError – If nodes is not (S, 2) with labels from 0 to num_nodes, or weights or values does not have S finite values.

Return type:

ndarray

References

Hagmann P, Cammoun L, Gigandet X, Meuli R, Honey CJ, Wedeen VJ, Sporns O. Mapping the structural core of human cerebral cortex. PLoS Biol 6 (2008) e159. Follows MRtrix3’s tck2connectome (version 3.0.8) with the default -stat_edge sum, and -stat_edge mean with -scale_length or -scale_file.

larmor.tractography.edit(tractogram, options)#

Runs a whole edit: selection, cropping, counting and resampling.

In this order:

  1. The length and weight limits and the include, ordered include, exclude and within regions give one selection, which keeps a streamline when it passes all of them. With inverse the selection is flipped, keeping the streamlines that fail at least one test; with no test given, every streamline is kept.

  2. The kept streamlines are cropped to the mask regions (with inverse, to the parts outside them), see crop.

  3. skip, every and then number or subsample count the selected streamlines: the first skip are dropped, then every every-th is kept starting with the first, then the first number (or a random subsample) of those. A streamline cropped into several pieces counts as one, and one cropped to nothing is gone. When fewer streamlines are left than number or subsample asks for, all are kept; subsample logs a warning.

  4. The result is resampled when step_size or num_points is given, see resample.

Only the tests given drop streamlines, so empty streamlines and negative weights are otherwise kept. Each piece keeps its points’ point_data and its streamline’s streamline_data; the reference is kept.

Parameters:

  • tractogram (Tractogram) – The streamlines, with streamline_data["weight"] when a weight limit is given.

  • options (EditOptions) – The selections and edits.

Returns:

Tractogram – A new tractogram with the edited streamlines, in input order.

Raises:

  • ValueError – If a weight limit is given and the tractogram has no “weight” entry, or a mask region is neither 3D nor 4D with a single volume.

  • TypeError – If a region is still text or a path (see load_region).

Return type:

Tractogram

References

Follows MRtrix3’s tckedit and tckresample (version 3.0.8). Tournier, J.-D. et al. MRtrix3: A fast, flexible and open software framework for medical image processing and visualisation. NeuroImage 202, 116137 (2019). doi:10.1016/j.neuroimage.2019.116137

larmor.tractography.edit_files(inputs, output, options, *, weights_in=None, weights_out=None, tsf_in=(), tsf_out=(), reference=None, force=False, lazy=False, batch_size=10000)#

Edits tractogram files into one output file, as edit does in memory.

The inputs are read and joined in order (see concatenate_tractograms), the weights and TSF values attached, the edit run and the result written with its weights and TSF files. Everything that can be checked from the paths and headers is checked before any streamline is read.

With lazy, each input is read, edited and written in batches of batch_size streamlines, and reading stops once number streamlines are written. What the join keeps is decided on the first batch of every input. An error during the run leaves the output marked as incomplete, but not the weights_out file, which holds the weights written so far.

The regions of options may be given as text (x,y,z,r or a mask image’s path), read with load_region.

The weights are streamline_data["weight"], from weights_in or else from a TRK input’s weight property, which weights_in replaces with a warning. Each tsf_in file becomes the point_data entry named after its stem; each tsf_out entry is written as <output name>_<name>.tsf, with only the tractogram extension removed from the output name (out.tck and fa give out_fa.tsf). A TCK output and the TSF files share one timestamp, that of a single TCK input that has one, else a new one.

Parameters:

  • inputs (Sequence[str | Path]) – The input tractograms, tck, trk or vtk/fib (each also gzipped), joined in this order.

  • output (str | Path) – The output tractogram, of any of these formats.

  • options (EditOptions) – The selections and edits.

  • weights_in (str | Path | None) – A weights file with one value per streamline of the single input. Defaults to None.

  • weights_out (str | Path | None) – The file to write the weights of the output streamlines to. Defaults to None.

  • tsf_in (Sequence[str | Path]) – TSF files with values per point of the single input. Defaults to none.

  • tsf_out (Sequence[str]) – Names of point_data entries to write as TSF files next to the output. Defaults to none.

  • reference (Grid | str | Path | None) – The grid of a TRK output when the inputs do not all have one, or an image whose grid it is (a NIfTI or MIF file, or an MRIToolkit fit mat); also passed to load_tractogram. Needed for MRIToolkit tractography inputs (mat). Defaults to None.

  • force (bool) – Whether to overwrite existing output files. Defaults to False.

  • lazy (bool) – Whether to read, edit and write in batches. Defaults to False.

  • batch_size (int) – Streamlines per batch with lazy.

Returns:

tuple[int, int] –

The number of streamlines read (fewer than in the inputs

when lazy reading stops early at number) and written. The read count is that of the streamlines passed to the edit: the first batches of later inputs, read before the stop to decide the join, are not counted.

Raises:

  • FileExistsError – If an output file exists and force is False.

  • FileNotFoundError – If the folder of an output file does not exist.

  • ValueError – Before any work: if no input is given, an extension is not a tractogram’s, weights_in or tsf_in is given with several inputs, two tsf_in files have the same stem, a weight limit or weights_out is given without weights, a tsf_out name is not provided by every input, a TRK output has no reference grid, or lazy is given with a VTK or compressed file, subsample, TSF files or an output that is also an input. During the work: if the weights or TSF values do not match the streamlines, a VTK input lacks the weights or TSF values asked for (VTK arrays are known only once read), or a file cannot be read or written.

Return type:

tuple[int, int]

References

Follows MRtrix3’s tckedit (version 3.0.8). Tournier, J.-D. et al. MRtrix3: A fast, flexible and open software framework for medical image processing and visualisation. NeuroImage 202, 116137 (2019). doi:10.1016/j.neuroimage.2019.116137

larmor.tractography.endpoint_nodes(tractogram, parcellation, *, radius=4.0, n_jobs=-1)#

Assigns the two endpoints of every streamline to regions of a parcellation.

With radius None or 0, an endpoint’s region is the label of its nearest voxel (0 outside the image). With a radius (the radial search), it is the label of the labelled voxel whose centre is nearest to the endpoint, if that centre is less than radius from it, and 0 if there is none. The radius applies to the endpoint’s own voxel as well: with voxels larger than the radius, an endpoint near a voxel’s corner may get no region although its own voxel is labelled.

Parameters:

larmor.tractography.resample(tractogram, *, step_size=None, num_points=None, n_jobs=-1)#

Resamples every streamline to a step size or to a number of points.

The new points lie on a cubic Hermite spline (tension 0.1) through each streamline’s points. With num_points, they are at equal arc lengths of the polyline. With step_size, they start from the middle point and go outward to each end, each at step_size (straight-line distance) from the previous one. The end points are kept, exactly with step_size and up to float32 rounding with num_points, unless the first or last segment has zero length. Streamlines of fewer than 2 points are kept as they are. Floating-point point_data is interpolated linearly and keeps its dtype; other entries take the value of the nearer original point. streamline_data and reference are kept. The result does not depend on n_jobs.

Parameters:

  • tractogram (Tractogram) – The tractogram to resample.

  • step_size (float | None) – The distance between consecutive new points, in mm. Defaults to None.

  • num_points (int | None) – The number of points of every new streamline, at least 2. Defaults to None.

  • n_jobs (int) – Number of threads, at most the cores; -1 is all cores. Defaults to -1.

Returns:

Tractogram –

A new tractogram with the resampled streamlines, in the same

order.

Raises:

ValueError – If neither or both of step_size and num_points are given, step_size is not a positive finite number, num_points is not an integer >= 2, or n_jobs is not an integer, 0 or below -1.

Return type:

Tractogram

larmor.tractography.track_density(tractogram, grid, *, weights=None, ends_only=False, upsample=None, n_jobs=-1)#

Counts the streamlines that pass through each voxel of a grid.

Each streamline is first upsampled on the cubic Hermite spline that resample uses. Every point is mapped to its nearest voxel, and the streamline adds 1, or its weight, once to each voxel it reaches, however many of its points fall there. Points outside the grid are skipped. With ends_only the image is the endpoint density instead: each of the two endpoints adds 1 (or the weight) to its voxel, so a streamline that ends twice in one voxel adds 2 there.

The grid may be finer than the image the streamlines were tracked on (see density_grid), which gives super-resolution track density imaging. By default each segment is split into enough pieces to bring the spacing of the points below a third of the smallest voxel size, so a fine grid has no gaps along a streamline. The result does not depend on n_jobs.

Parameters:

  • tractogram (Tractogram | Iterable[Tractogram]) – The streamlines, in world coordinates (mm); or an iterable of tractograms, such as the batches of iter_tractogram, whose densities are added up.

  • grid (Grid) – The grid of the image to fill.

  • weights (ndarray | None) – (S,) one weight per streamline, in the order of the streamlines (across all batches), such as SIFT2’s. Defaults to None, every streamline counting 1.

  • ends_only (bool) – Whether to map only the two endpoints of each streamline. Defaults to False.

  • upsample (int | None) – The number of pieces every segment is split into, at least 1 (1 maps only the stored points). Defaults to None, each segment’s own number from its length and the grid. Not used with ends_only.

  • n_jobs (int) – Number of threads, at most the cores; -1 is all cores. Defaults to -1.

Returns:

A 3D volume on grid – uint32 counts without weights, float32 sums of the weights with them.

Raises:

ValueError – If weights does not have one finite value per streamline, upsample is not an integer of at least 1, or n_jobs is 0 or below -1.

Return type:

Volume

larmor.tractography.tract_profile(bundle, maps, *, num_points=100, weighting=Weighting.GAUSSIAN, start=None, n_jobs=-1)#

Computes the profile of maps (FA, MD, …) along a bundle.

The profile points are the num_points nodes of a centreline of the bundle, and every point of every streamline is assigned to its nearest node (Chandio et al. 2020), so that node n holds the same place along the bundle for every streamline. A streamline that covers only part of the bundle contributes only to the nodes it reaches. Each map is sampled with trilinear interpolation at points a fifth of the node spacing apart along each streamline. The profile at a node is the weighted mean of the streamlines’ mean values there; points whose nearest voxel is outside a map and non-finite values are left out. With a map that changes along the bundle, the values of the first and last nodes lie about a quarter of the node spacing inward.

Without start, the profile starts at the end of the bundle that is left, posterior or inferior (in world coordinates, RAS+) along its main axis, such as the brainstem end of a corticospinal tract or the left end of the corpus callosum. When the axis’s two largest components are within 20% of each other in size, a small change in the bundle can move the start to the other end, and a warning says so; pass start to make every subject’s profile start at the same end. With start, each streamline is reversed when its last point is nearer to start than its first point.

With “gaussian” weighting, each streamline’s value at a node is weighted by the probability that it belongs to the bundle there, under a 3D Gaussian fitted to the streamlines’ positions at the node (Yeatman et al. 2012). With “mean”, all streamlines weigh the same.

Parameters:

  • bundle (Tractogram) – The streamlines of one bundle, in world coordinates (mm), each of at least 2 points.

  • maps (Mapping[str, Volume]) – The maps to profile, by name; each a 3D image, or a 4D one with a single volume.

  • num_points (int) – The number of profile points, N, at least 2. Defaults to 100.

  • weighting (Weighting | str) – “gaussian” or “mean”. Defaults to “gaussian”.

  • start (ArrayLike | None) – A point (x, y, z) in mm near the end of the bundle where the profile should start. Defaults to None, the rule above.

  • n_jobs (int) – Number of threads for the resampling, at most the cores; -1 is all cores. Defaults to -1.

Returns:

TractProfile –

The profile of each map, the centreline and the reversed

streamlines.

Raises:

ValueError – If the bundle is empty or has a streamline of fewer than 2 points, num_points is below 2, weighting is unknown, start is not three numbers, or a map has several volumes.

Return type:

TractProfile

References

Yeatman JD, Dougherty RF, Myall NJ, Wandell BA, Feldman HM. Tract profiles of white matter properties: automating fiber-tract quantification. PLoS One 7, e49790 (2012). doi:10.1371/journal.pone.0049790. Chandio BQ, Risacher SL, Pestilli F, et al. Bundle analytics, a computational framework for investigating the shapes and profiles of brain pathways across populations. Sci Rep 10, 17149 (2020). doi:10.1038/s41598-020-74054-4.
