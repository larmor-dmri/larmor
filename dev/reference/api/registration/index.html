larmor.registration#

Reading the transforms of ANTs, FSL and MRtrix3 registrations and applying them.

Transforms map points in world coordinates (RAS+), in mm. A transform read from a file maps points of the reference space to the input space, the direction used to resample an image. Streamlines and surfaces move the other way, so they need the inverse to follow the image.

larmor.registration.apply_transform(data, transform, *, reference=None, interpolation='linear', reorient=None)#

Brings an image, tractogram or surface into a reference space.

transform maps reference points to the data’s space, as load_registration returns it. An image is resampled with it; the points of a tractogram or surface move with its inverse, so that every kind of data lands in the same space.

Parameters:

  • data (Volume | Tractogram | Surface) – A Volume, Tractogram or Surface, in world coordinates (RAS+).

  • transform (Transform) – Maps reference points to the data’s points, in mm.

  • reference (Grid | None) – The reference grid; needed for an image, stored as the reference of a tractogram or surface.

  • interpolation (Literal['nearest', 'linear', 'cubic']) – For an image, as in transform_volume.

  • reorient (Literal['peaks', 'tensor'] | None) – For an image, as in transform_volume.

Returns:

The data in the reference space, of the same type.

Raises:

ValueError – If an image has no reference grid, or as the function used.

Return type:

Volume | Tractogram | Surface

larmor.registration.load_registration(files, *, data_grid=None, reference_grid=None, inverse=False, format=None, warp_type=None, fsl_input_grid=None, fsl_reference_grid=None)#

Reads the files of a registration as one transform into a reference space.

Pass the result to apply_transform to bring an image, tractogram or surface into the reference space. The result maps reference points to data points, the direction transform_volume takes.

The files are those that resample an image into the reference space, listed in the order antsApplyTransforms takes its -t options, so the first file takes the reference grid’s points. A warp can be given as a pair (file, inverse_file) with the inverse its tool wrote (ANTs’ InverseWarp, invwarp, warpinvert), which is then used instead of inverting the warp numerically. With inverse the data goes the other way, from the reference space into the space the files bring images from.

FSL files need the grids of the FLIRT or FNIRT run’s input and reference images. They default to the data’s grid and reference_grid, swapped with inverse; data without a grid (streamlines, surfaces) needs fsl_input_grid going forward and fsl_reference_grid with inverse.

Parameters:

  • files (Sequence[str | Path | tuple[str | Path, str | Path]]) – The files, or pairs of a warp and the inverse its tool wrote.

  • data_grid (Grid | None) – The grid of the data, if it is an image.

  • reference_grid (Grid | None) – The grid of the reference space.

  • inverse (bool) – Go from the reference space into the space of the files’ inputs.

  • format (str | None) – “ants”, “fsl” or “mrtrix”, when the files alone do not tell.

  • warp_type (str | None) – The warp type of the warp fields, as in load_transform.

  • fsl_input_grid (Grid | None) – The FSL run’s input image grid, if not the default.

  • fsl_reference_grid (Grid | None) – The FSL run’s reference image grid, if not the default.

Returns:

The transform, reference points to data points.

Raises:

ValueError – As load_transform.

Return type:

Transform

larmor.registration.load_transform(path, *, format=None, warp_type=None, fsl_input_grid=None, fsl_reference_grid=None)#

Reads a transform file of any supported format, chosen from the file if needed.

Without format: an ITK text header or a binary mat is ANTs, a text mat is a FLIRT matrix, and other text files are MRtrix3 when they have MRtrix3’s # command_history: comment or 3 rows of 4 numbers. Any other 4x4 text matrix can be FLIRT or MRtrix3, so it needs format. A 5D NIfTI is an ANTs warp and a mif an MRtrix3 deformation field; a 4D NIfTI warp can come from FSL or MRtrix3, so it needs format too. Every transform maps reference points to input points, as the tools use them for images.

Parameters:

  • path (str | Path) – The transform file.

  • format (str | None) – “ants”, “fsl” or “mrtrix”, when the file alone does not tell.

  • warp_type (str | None) – For a warp field, how it stores where each voxel comes from: “deformation” (positions, MRtrix3’s default) or “displacement” for MRtrix3, “relative” (FSL’s default) or “absolute” for FSL. Checked against the field’s values. ANTs warps are always displacements.

  • fsl_input_grid (Grid | None) – The grid of the FSL run’s input image, needed for FSL files.

  • fsl_reference_grid (Grid | None) – The grid of the FSL run’s reference image, needed for a FLIRT matrix.

Returns:

The transform.

Raises:

ValueError – If the format is unknown or cannot be told, an FSL file lacks a grid, or the warp type does not fit the format or the data.

Return type:

Transform

larmor.registration.read_ants_transform(path)#

Reads an affine or a displacement field written by ANTs.

The transform maps points of the fixed image (the reference grid, -r of antsApplyTransforms) to the moving image, the direction antsApplyTransforms uses for images as listed with -t, and antsApplyTransformsToPoints for points. Bringing streamlines from the moving into the fixed space needs its inverse (for a warp, the InverseWarp file antsRegistration writes beside it).

The transform is converted from ITK’s LPS coordinates to RAS+ as read.

Parameters:

path (str | Path) – An affine as a binary mat file (0GenericAffine.mat, MATLAB version 4) or an ITK text file (txt, tfm), of type AffineTransform or MatrixOffsetTransformBase in 3D; or a displacement field as a NIfTI file (1Warp.nii.gz, (X, Y, Z, 1, 3), mm, LPS).

Returns:

The affine or the displacement field, in world coordinates (RAS+) in mm.

Raises:

ValueError – If the file is not one of those, or holds another transform type (convert it with ConvertTransformFile --convertToAffineType).

Return type:

AffineTransform | DisplacementField

larmor.registration.read_flirt_transform(path, input_grid, reference_grid)#

Reads an FSL FLIRT matrix (-omat) as a transform of world points.

FLIRT’s matrix works in FSL’s scaled voxel coordinates of the input and reference images, so it needs both grids. The transform returned maps points of the reference image to the input image, the inverse of FLIRT’s matrix and the direction flirt -applyxfm uses to resample the input. Moving points from the input into the reference space needs its inverse.

Parameters:

  • path (str | Path) – The text file of 4 rows of 4 numbers.

  • input_grid (Grid) – The grid of FLIRT’s -in image.

  • reference_grid (Grid) – The grid of FLIRT’s -ref image.

Returns:

The affine, reference to input, in world coordinates (RAS+) in mm.

Raises:

ValueError – If the file is not a 4x4 matrix of numbers.

Return type:

AffineTransform

larmor.registration.read_fsl_warp(path, input_grid, *, relative=True)#

Reads an FSL warp field (fnirt --fout, convertwarp, invwarp) as a transform.

The field lies on the reference image’s grid and holds where each reference voxel comes from in the input image, in FSL’s scaled voxel coordinates, as a displacement (relative, FSL’s default) or as the coordinates themselves (absolute, --abs). The transform maps points of the reference image to the input image, the direction applywarp uses to resample the input. Moving points the other way needs its inverse (invwarp’s output, or the numerical inverse).

Fields of spline coefficients (fnirt --cout) are not read; convert them with fnirtfileutils --withaff or convertwarp first.

Parameters:

  • path (str | Path) – The NIfTI file, (X, Y, Z, 3).

  • input_grid (Grid) – The grid of the input image (applywarp’s -i).

  • relative (bool) – Whether the field holds displacements (True) or absolute coordinates. The values are checked against it: absolute coordinates lie near each voxel’s own coordinates, displacements near zero.

Returns:

The displacement field, in world coordinates (RAS+) in mm.

Raises:

ValueError – If the file is not a 4D image with 3 volumes, or its values look like the other kind of field.

Return type:

DisplacementField

larmor.registration.read_mrtrix_transform(path)#

Reads an MRtrix3 linear transform (mrregister, transformconvert).

The matrix is in scanner coordinates (RAS+, mm) and, as mrtransform -linear uses it, maps points of the template (reference) image to the input image. Moving points from the input into the template space needs its inverse.

Parameters:

path (str | Path) – A text file of 3 or 4 rows of 4 numbers; # starts a comment.

Returns:

The affine, in world coordinates (RAS+) in mm.

Raises:

ValueError – If the file is not a 3x4 or 4x4 matrix of numbers.

Return type:

AffineTransform

larmor.registration.read_mrtrix_warp(path, *, displacement=False)#

Reads an MRtrix3 deformation or displacement field as a transform.

A deformation field holds, at each voxel of the template grid, the position in the input image it comes from (scanner coordinates, RAS+, mm); a displacement field holds that position minus the voxel’s own. Either way the transform maps template points to input points, as mrtransform -warp uses it to resample an image; tcktransform moves streamlines from the template space into the input space with the same map_points. NaN marks voxels without a position.

mrregister’s 5D warps (both halves of a symmetric registration) are not read; convert one with warpconvert -type warpfull2deformation first.

Parameters:

  • path (str | Path) – The image (mif, nii, …), (X, Y, Z, 3).

  • displacement (bool) – Whether the field holds displacements instead of positions. The values are checked against it: positions lie near each voxel’s own position, displacements near zero.

Returns:

The displacement field, in world coordinates (RAS+) in mm.

Raises:

ValueError – If the image is not (X, Y, Z, 3), or its values look like the other kind of field.

Return type:

DisplacementField

larmor.registration.transform_surface(surface, transform, *, reference=None)#

Moves every vertex of a surface with a transform.

Each vertex p becomes transform(p), the same direction as transform_tractogram and the opposite of transform_volume. Where the transform reflects at every vertex, such as an affine with a flip, the triangles’ vertex order is reversed so that normals still point out.

  • reference (Grid | None) – The grid of the output space, stored as the result’s reference. None leaves it unknown.

Returns:

A new surface with the moved vertices and the same vertex_data.

larmor.registration.transform_volume(volume, transform, reference, *, interpolation='linear', reorient=None, fill=0.0)#

Resamples an image onto a reference grid through a transform.

Each voxel of the reference grid, at world position p, takes the image’s value at transform(p). The transform therefore maps points of the reference space to the image’s space, the direction transform files store, so the same file and reference image give the result of antsApplyTransforms, flirt -applyxfm, applywarp or mrtransform.

A point within half a voxel beyond the image’s outer voxel centres takes the edge value; a point further out gets fill.

Directions stored in the image are reoriented when reorient says how they are stored, following Alexander et al. (2001):

  • “peaks”: vectors in groups of 3 per voxel, shape (X, Y, Z, 3K), each turned by the local transform and kept at its length. Needs interpolation="nearest".

  • “tensor”: diffusion tensors as their 6 elements (xx, xy, xz, yy, yz, zz), interpolated element by element, then rotated by finite strain.

FODs are not reoriented.

Parameters:

  • volume (Volume) – The image, 3D or 4D; each volume of a 4D image is resampled alike.

  • transform (Transform) – Maps reference points to image points, in world mm (RAS+).

  • reference (Grid) – The output grid. The result takes its NIfTI sform and qform codes, so an image resampled onto a template is labelled in the template’s space.

  • interpolation (Literal['nearest', 'linear', 'cubic']) – “nearest” (for labels; keeps the data type), “linear” (the default) or “cubic” (B-spline of order 3).

  • reorient (Literal['peaks', 'tensor'] | None) – How directions are stored, if they are: “peaks” or “tensor”.

  • fill (float) – The value outside the image.

Returns:

The resampled image on reference, float32 (float64 for a float64 image) unless the interpolation is “nearest”, which keeps the stored values and their scaling.

Raises:

ValueError – If reorient does not match the image’s last axis, or “peaks” is asked for with an interpolation other than “nearest”.

Return type:

Volume

References

Alexander DC, Pierpaoli C, Basser PJ, Gee JC. Spatial transformations of diffusion tensor magnetic resonance images. IEEE Trans Med Imaging 20 (2001) 1131-1139.
